# OurTree (`ourtree_app`)

Семейный альбом: профили, таймлайн событий, календарь и медиатека. Flutter,
Riverpod, Hive, локализация на `en`, `ru`, `be`, `uk`.

## Сборки и установка

### Android (APK для установки вручную)

```powershell
flutter build apk --release                  # универсальный APK (~152 МБ: FFmpeg GPL)
flutter build apk --release --split-per-abi  # arm64 ~57 МБ, armeabi-v7a ~71 МБ, x86_64 ~61 МБ
```

Файлы появляются в `build/app/outputs/flutter-apk/`; копии для передачи на телефон —
в `dist/` (`ourtree-0.4.0-android.apk`, `ourtree-0.4.0-android-arm64.apk`).

Release подписан debug-ключом (см. `android/app/build.gradle.kts`) — для установки
«из файла» этого достаточно, для Google Play нужен собственный keystore.

Установка: разрешить установку из неизвестных источников для файлового менеджера
или браузера и открыть APK. На современных телефонах подходит `...-arm64.apk`.

### Web и установка на iPhone (PWA)

```powershell
flutter build web --release
firebase deploy --only hosting --project ourtree-dev
```

Раздача — Firebase Hosting: <https://ourtree-dev.web.app> (секция `hosting` в
`firebase.json`, публикуется каталог `build/web`). iOS ставит веб-версию как PWA:

1. открыть ссылку **в Safari** (не в Chrome — там нет «На экран „Домой“»);
2. «Поделиться» → «На экран „Домой“» → «Добавить»;
3. запускать с иконки: приложение открывается на весь экран, без адресной строки.

Мета-теги (`apple-mobile-web-app-*`, `theme-color`, `apple-touch-icon`) — в
`web/index.html`, цвета и иконки — в `web/manifest.json` и `web/icons/`.
Нативная iOS-сборка (`.ipa`) собирается только на macOS: `flutter build ipa`.

### Установка на iPhone: Safari, а не Chrome

На iOS все браузеры работают на WebKit (требование Apple), поэтому приложение
выглядит одинаково. Но web-push (уведомления) там поддерживается только в
**установленном** веб-приложении и только с iOS 16.4+:

1. открывайте ссылку в **Safari** (Chrome на iPhone не даёт гарантированного
   standalone-режима и push для установленных с него веб-приложений);
2. «Поделиться» → «На экран „Домой“»;
3. запускайте с иконки — только в этом режиме работает `Notification.requestPermission()`
   и приходят пуши.

Учтите, что у каждого браузера своё локальное хранилище (IndexedDB + Hive):
PWA, установленное из Safari и из Chrome, — это два независимых локальных
архива. Семья в облаке у них одна, поэтому после подключения данные
синхронизируются, но «локальные» правки демо-режима между ними не переносятся.

### Web-push (VAPID)

Публичный VAPID-ключ берётся в Firebase Console: **Project settings → Cloud
Messaging → Web Push certificates → Generate key pair** (нужно
зарегистрированное веб-приложение проекта). Ключ передаётся в сборку, а не
хранится в коде:

```powershell
# dart_defines.json (в .gitignore)
# { "FIREBASE_VAPID_KEY": "B..." }
flutter run -d chrome --dart-define-from-file=dart_defines.json
flutter build web --release --dart-define-from-file=dart_defines.json
```

В коде ключ читается как `String.fromEnvironment('FIREBASE_VAPID_KEY')` и
используется в `FirebaseMessaging.instance.getToken(vapidKey: ...)`.

## Локальные данные и бэкапы

Архив семьи хранится в Hive под единым ключом `family_data` и не зависит от
языка интерфейса: смена языка меняет только подписи и демо-архив (пока
пользователь ничего не менял). Раньше копия хранилась отдельно для каждого
языка (`family_data_<код>`) — миграция схемы 2 переносит её автоматически.

Кадрирование (точка фокуса `position` и масштаб `zoom`) входит в архив для
участников, событий, связей медиатеки и общего фото семьи, поэтому резервная
копия восстанавливает снимки «как были», без повторной правки. Кадр управляется
только перетаскиванием и «щипком» (включая трекпад); кнопка сброса возвращает
центр и масштаб `1.0`. Ползунков и кнопок «приблизить/отдалить» нет. Тексты
снимка помечаются пользовательскими (`nameIsCustom`/`subtitleIsCustom`), чтобы
демо-архив другого языка их не перекрыл.

«Откат к демонстрационным данным» удаляет только локальный архив и требует
подтверждения; резервную копию можно сделать прямо из диалога. Облачные данные
при этом не трогаются — чтобы удалить и их, используйте кнопку «Удалить данные
семьи из облака» в «Общие настройки → Облако» (диалог отката на неё ссылается).

## Облако (в разработке)

Синхронизация — Cloud Firestore + Firebase Storage. Авторизация — Firebase Auth:
анонимная сессия для демо-режима и серверный логин/пароль для аккаунтов семьи
(`accountLogin` → custom token, `auth.uid == accountId`). Покупки — RevenueCat
(iOS/Android/Web) и Telegram-бот + Cloud Functions (РФ/РБ). Локальные данные
остаются в Hive и работают офлайн.

### Серверные аккаунты (логин и пароль)

Аккаунты семьи хранятся в Firestore (`accounts/{accountId}`), пароль проверяют
Cloud Functions (`functions/src/accounts.ts`): scrypt с индивидуальной солью.
Клиент получает Firebase custom token, поэтому `auth.uid == accountId` — вход
работает на любом устройстве, а членство в семье переезжает вместе с аккаунтом.

| Функция | Что делает |
|---|---|
| `accountRegister` | создаёт аккаунт: логин 2–32 символа, пароль от 4 символов |
| `accountLogin` | проверяет пароль, переносит членство со старого uid, выдаёт custom token |
| `accountList` | администратор получает все аккаунты, остальные — только свой |
| `accountUpdate` | имя, роль, пароль, видимость участников |
| `accountDelete` | удаляет аккаунт, его логин и членство в семьях |

Первый зарегистрированный аккаунт получает роль `admin` (бутстрап в
`accountMeta/bootstrap`), дальше роли выдаёт только администратор; обычная
регистрация создаёт `viewer`. Свой аккаунт удалить нельзя, владельца семьи —
тоже (сначала удалите семью или передайте владение).

Клиент (`ServerAuth`):

1. `accountLogin`; при `not-found`/`unavailable` проверяет локальную копию и
   переносит её на сервер (`accountRegister` с тем же id) — так аккаунты,
   созданные до появления серверной авторизации, переезжают при первом входе;
2. `signInWithCustomToken` — `auth.uid` становится id аккаунта;
3. администратор дополнительно подтягивает список аккаунтов.

Если сервер недоступен, вход продолжает работать по локальной копии (хеш
пароля хранится только на устройстве), а изменения прав уходят на сервер при
следующей успешной операции. Служебные коллекции `accountLogins` и
`accountMeta` закрыты правилами — писать в них может только Admin SDK.

Для выдачи custom token сервисному аккаунту Cloud Functions нужна роль
`roles/iam.serviceAccountTokenCreator` (иначе `createCustomToken` падает с
`Permission 'iam.serviceAccounts.signBlob' denied`). В `ourtree-dev` она выдана
аккаунту `477705174790-compute@developer.gserviceaccount.com` на уровне проекта:

```powershell
gcloud projects add-iam-policy-binding ourtree-dev `
  --member="serviceAccount:477705174790-compute@developer.gserviceaccount.com" `
  --role="roles/iam.serviceAccountTokenCreator"
```

Поток загрузки (`MediaRepository.uploadAsset`):

1. `prepareMediaUpload` — сжатие фото / транскод видео (ffmpeg);

3. локальная копия в каталог приложения (офлайн-доступ);
4. `putData` в Storage + `getDownloadURL`;
5. ассет обновляется: `source = downloadUrl`, `uploadState = ready`.

Если семья не подключена (демо-режим) — файл, как и раньше, сохраняется в Hive
(`hive://…`), и приложение показывает уведомление `mediaLocalOnlyNotice`:
«файл останется только на этом устройстве». Так работают все четыре точки
загрузки: медиатека, фото семьи в настройках, редактор участника, редактор события.

Сетевые изображения рендерятся через `CachedNetworkImage` с общим
`CacheManager`: первый показ — загрузка, повторный — с диска (на web — браузерный кэш).

Ограничения: в UI 20 МБ на файл, в правилах Storage — 300 МБ.

**Массовая выгрузка.** В медиатеке есть кнопка «Загрузить всё локальное (N)»:
она проходит по `mediaLibrary`, берёт только файлы без `storagePath`
(`hive://…` и локальные копии) и отправляет их в Storage последовательно,
обновляя прогресс. Удаление ассета в медиатеке удаляет и объект в Storage,
и локальную копию.

**Очередь выгрузки (outbox).** Если сеть пропала, файл не теряется: байты
остаются локально, а операция пишется в Hive (`media_outbox`) и получает статус
`queued`. Очередь автоматически отправляется при старте приложения и при
появлении сети (`connectivity_plus`); в медиатеке видна кнопка
«В очереди: N — отправить» для ручного повтора. Ошибки не блокируют остальные
файлы — у каждой операции считаются `attempts` и `lastError`.

### Синхронизация текстов (люди, события, медиатека)

| Что | Где |
|---|---|
| Документ состояния | `families/{familyId}/state/current` |
| Поля | весь архив (`familyName`, `members`, `timelineEvents`, `mediaLibrary`, …) + `updatedAt`, `schemaVersion` |
| Чтение | при подключении семьи (`FamilySyncController.pull`) |
| Запись | создание семьи (`seedFamily`) + любое локальное изменение → дебаунс 2 с → `push` |
| Статус | `SyncStatus` (`loading/saving/saved/error`) |

**Передача архива в новую семью.** Сразу после создания семьи локальный архив
выгружается в `state/current` (`FamilySyncController.seedFamily`), а все сущности
получают отметку «сейчас». Без этого документ состояния оставался пустым, и
второе устройство, подключившееся по коду, показывало свой **демо-архив** —
в облаке ведь нечего было забирать. Если документ состояния пуст у семьи,
созданной старой версией, владелец досылает архив при следующем запуске
(`pull` → `seedFamily`).

**Демо-архив не переезжает в семью.** При слиянии учитываются только сущности
с локальной отметкой времени (`dropUnstampedLocal`): человек, событие или файл
без отметки — это демо-архив (или архив другой семьи), его место занимает
серверная копия. Иначе после присоединения по коду в общем альбоме оставались
бы демо-люди, события и фотографии, а первая же правка отправила бы их в облако.

Если демо-контент уже попал в семью (её состояние было создано старой версией),
проще пересоздать семью: владелец нажимает «Удалить данные семьи из облака» и
создаёт семью заново, остальные отключаются и подключаются по новому коду.

**Индикатор статуса.** В шапке приложения (рядом с шестерёнкой) показывается
состояние синхронизации: «Синхронизация…», «Сохранение…», «Сохранено», «Нет связи».
В демо-режиме (семья не подключена) индикатор скрыт.

### Резервные копии и синхронизация

Снимок (`BackupsNotifier`) хранит JSON архива, байты файлов медиатеки (`media`),
файлы из ассетов (`assets`) и аккаунты. При восстановлении:

1. байты из снимка кладутся в Hive, а ссылки `/photos/...` и `assets/photos/...`
   в архиве переписываются на `hive://restored-...` — фото остаются доступны даже
   если исходных файлов в сборке больше нет;
2. название семьи помечается как пользовательское (`nameIsCustom`), чтобы его не
   подменило название демо-архива;
3. архив помечается локальными правками и сразу выгружается в облако
   (`FamilySyncController.adoptLocalArchive`). Без этого сущности из снимка
   считались «чужими» и следующий `pull` заменял их серверной копией — визуально
   «бэкап не восстановился, осталась демоверсия»;
4. серверные записи, которых нет в снимке (демо-люди, события и файлы, попавшие
   в облако старым слиянием), получают `entityDeletedAt` — снимок заменяет
   содержимое семьи, а не смешивается с ним;
5. на время восстановления серверное слияние приостановлено
   (`beginReplace`/`endReplace`), а `pull` запоминает локальный архив до запроса:
   ответ, прочитанный до восстановления, не применяется.

Тексты после восстановления уезжают в облако сразу, а **файлы** — кнопкой
«Загрузить всё локальное (N)» в медиатеке: пока файл не в Firebase Storage,
другие устройства видят ссылку `hive://...`, которой у них нет.

**Файлы из сборки не теряются.** При импорте снимка встроенные `/photos/...`
переписываются в `hive://restored-<sha256(путь)[:24]>`, а байты кладутся в Hive.
Если приложение переустановили (Hive очистился), ссылка остаётся «битой» — но
сам снимок по-прежнему лежит в `assets/photos/`. `RestoredMedia`
(`lib/core/media/restored_media.dart`) повторяет ту же формулу хеша и находит
исходный ассет: фото снова видно в таймлайне, профилях и медиатеке, а кнопка
«Загрузить всё локальное» выгружает его в Storage. Для файлов, которых нет ни в
Hive, ни в сборке (добавлены на другом устройстве и не выгружены), показываем
подсказку `mediaUploadUnavailableHint`.

**Слияние по сущностям.** Каждый человек, событие и файл медиатеки хранит
собственную отметку времени (`entityUpdatedAt` в документе семьи). При
подключении и при получении серверной копии архив **сливается по сущностям**:
побеждает более свежая версия, а правки разных устройств в разных людях/событиях
не перетирают друг друга. Отметки лежат локально в Hive
(`family_sync_stamps_<familyId>`), поэтому переживают перезапуск приложения.

**Удаления (tombstones).** Удалённые человек, событие или файл получают метку
`entityDeletedAt` и остаются в документе как «надгробие», пока не разъедутся по
всем устройствам (срок жизни — 60 дней). При слиянии сущность исчезает, если
метка удаления новее последней правки; пересоздание сущности позже удаления
снимает надгробие. Так удалённое на телефоне не «воскресает» на планшете.

Ограничения текущей версии (v2): весь архив по-прежнему отправляется одним
документом (правка одной записи перезаписывает документ целиком). Правки
разных устройств в разных людях/событиях не перетирают друг друга, но два
устройства, меняющие **одного** человека одновременно, разрешаются по времени
последней записи (LWW на уровне сущности). Realtime-подписки (`onSnapshot`) нет:
обновления подтягиваются при подключении семьи и по кнопке «Синхронизировать».

## Приватность и удаление данных

Данные семьи принадлежат владельцу, и он может стереть их полностью.

| Действие | Что происходит | Кто может |
|---|---|---|
| **Отключить это устройство** | Локальный архив остаётся. Не-владелец удаляет только свой документ членства — облако живёт для остальных. Владелец, оставшийся один, при отключении стирает данные семьи из облака целиком (иначе семья осталась бы «мусором» без владельца) | участник; владельцу при других участниках недоступно |
| **Удалить данные семьи из облака** | Необратимо удаляются все файлы Storage (`families/{fid}/**`), документы содержимого и участников, коды приглашений и сам документ семьи; локальный архив остаётся | только владелец |

Владелец не может просто «выйти», пока в семье есть другие активные участники:
семья осталась бы без владельца и её никто не смог бы удалить. Ему доступны
полное удаление данных или сохранение устройства подключённым.

Порядок удаления продиктован правилами безопасности: сначала файлы (пока
членство активно и Storage Rules разрешают запись), затем коды приглашений и
содержимое, затем документ семьи и последним — собственный документ участника.
Удаление идёт пачками по 400 документов (лимит Firestore — 500 на batch).

Документ семьи хранит `updatedAt` (мс эпохи), который правило `freshTimestamp()`
сверяет с временем сервера: клиент не может «перебить» чужие правки датой из
прошлого. Премиум-поля серверные — клиент не вправе их менять.

### Автоматическая уборка в облаке

Клиентское удаление может не дойти до конца (приложение закрыли, сеть пропала,
данные стёрли из консоли). Поэтому Cloud Function `scheduledCleanup`
(`functions/src/cleanup.ts`) раз в сутки в 03:00 по Берлину делает три прохода:

| Проход | Что удаляет | Задержка |
|---|---|---|
| Просроченные приглашения | `inviteCodes` с истёкшим `expiresAt` | 1 сутки после истечения |
| Брошенные файлы | объекты Storage `families/{fid}/**`, у которых нет документа семьи | 1 сутки с создания файла |
| Мёртвые семьи | документ семьи со всеми подколлекциями, файлами и кодами | 1 сутки, если участников нет вовсе; 30 суток, если все вышли |

Задержки защищают от гонок: свежую загрузку или только что созданную семью
уборка не тронет. Функция идемпотентна и безопасна для повторного запуска;
проверить её без удаления можно через `runCleanup({ dryRun: true })`.

### CORS для медиа (обязательно для веба)

Flutter Web (CanvasKit) загружает изображения через `fetch`, поэтому Storage
обязан отдавать `Access-Control-Allow-Origin`. Без этого загруженные в облако
фото и видео видны на Android, но **не отображаются на вебе/PWA** (демо-фото из
сборки работают всегда — они лежат в бандле).

Конфигурация хранится в `storage.cors.json`. Применить к бакету:

```powershell
# через gsutil (Google Cloud SDK)
gsutil cors set storage.cors.json gs://ourtree-dev.firebasestorage.app
```

Без gcloud SDK — тем же содержимым через REST API Storage:

```
PATCH https://storage.googleapis.com/storage/v1/b/ourtree-dev.firebasestorage.app?fields=cors
Authorization: Bearer <access-token проекта>
Content-Type: application/json

{ "cors": [ ...содержимое storage.cors.json... ] }
```

Проверка (должен появиться заголовок `Access-Control-Allow-Origin`):

```powershell
curl.exe -sI -H "Origin: https://ourtree-dev.web.app" "<download-url>" |
  Select-String -Pattern "Access-Control-Allow-Origin"
```

Если появится собственный домен — добавьте его в `origin` и примените заново.

## Что нового в 0.5.0

- **Живая синхронизация.** Клиент подписывается на `families/{fid}/state/current`
  (Firestore `snapshots`), поэтому правки с другого устройства появляются без
  перезапуска приложения. Отметки сущностей пишутся картой (`entityUpdatedAt`,
  `entityDeletedAt`), старый строковый формат тоже читается.
- **Слияние при записи.** Перед `set()` архив сливается с серверной копией по
  отметкам сущностей: одновременные правки двух устройств больше не затирают
  друг друга. Неотправленные изменения помечаются в Hive и повторяются при
  следующем запуске или подключении.
- **Медиа.** Путь к локальному файлу (`localPath`) больше не уезжает в облако и
  в файл резервной копии. Локальные файлы автоматически выгружаются в Storage,
  как только семья подключена (провайдер `mediaCloudSyncProvider`), а не только
  по кнопке «Загрузить всё локальное».
- **Вход в аккаунт.** `accountLogin` ищет семью по владению, `memberUids` и
  документу участника; триггер `familyMemberJoined` дописывает приглашённого в
  денормализованные списки семьи. После входа приложение сразу подтягивает архив.
- **Демо-режим.** При первой правке демо-архива показывается диалог «изменения
  останутся на этом устройстве» и метка в шапке; после подключения семьи они
  исчезают.
- **Импорт/экспорт бэкапа.** На вебе (включая PWA на iPhone) отключена
  авт-отмена выбора файла по возврату фокуса, файл проверяется по расширению и
  размеру, битые медиа-записи больше не отменяют импорт целиком. Экспорт на вебе
  считается успешным, когда браузер скачал файл.
- **Восстановлены** фото `media-006_1.jpg`, `media-009_image.jpg`,
  `media-016_image.jpg`, `media-030_image.jpg`: на них ссылались архивы, но файлы
  были удалены из сборки в `c54fe7c`.

  «Рождение Даниила» (и другие демо-рождения первой версии) и отправляет
  удаление в облако через отложенные надгробия.
