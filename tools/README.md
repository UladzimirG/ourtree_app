# Инструменты разработки

Два PowerShell-скрипта для работы с демо-архивом. Запускать из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\validate_family_data.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools\swap_demo_media.ps1 -DryRun
```

## validate_family_data.ps1

Проверяет четыре файла в `assets/data/` (`family_ru/be/uk/en.json`):

- JSON валиден, `familyName` не пустой;
- `id` людей и событий уникальны внутри файла;
- `timelineEvents[].memberId` существует среди людей;
- даты в формате `YYYY-MM-DD`;
- все ссылки `/photos/…` и `assets/…` реально есть в `assets/photos/`;
- наборы `id` (люди и события) совпадают во всех четырёх языках.

Код выхода `1`, если есть ошибки — удобно для CI. Флаг `-Quiet` отключает вывод.

## swap_demo_media.ps1

Заменяет 14 демонстрационных файлов на новые. Имена целевых файлов не меняются, поэтому JSON править не нужно.

1. Положите изображения в `new_media/`.
2. Прогоните с `-DryRun`, чтобы увидеть таблицу «слот → файл → размер → пиксели».
3. Запустите без `-DryRun`, чтобы заменить.

Параметры:

| Параметр | Смысл |
|---|---|
| `-Source <папка>` | откуда брать файлы (по умолчанию `new_media`) |
| `-Mode ByOrder` | 14 файлов в алфавитном порядке → слоты по таблице (по умолчанию) |
| `-Mode ByName` | имена файлов совпадают с именами слотов |
| `-DryRun` | ничего не менять, только показать план |
| `-NoBackup` | не копировать старые файлы в `build/media_backup/<дата>` |

## export_texts.js / import_texts.js — правка текстов сразу во всех языках

Демо-тексты лежат в четырёх JSON, поэтому менять их вручную в каждом файле
неудобно. Этот мини-цикл даёт одну таблицу на все локализации:

```powershell
node tools\export_texts.js     # создаёт demo_texts.tsv
# ... правите demo_texts.tsv в Excel / Google Sheets / VS Code ...
node tools\import_texts.js     # вносит правки в 4 JSON точечно
powershell -NoProfile -ExecutionPolicy Bypass -File tools\validate_family_data.ps1
```

Формат таблицы (TSV, UTF-8 с BOM — Excel открывает кириллицу корректно):

| kind | id | field | ru | be | uk | en |
|---|---|---|---|---|---|---|
| global | - | familyName | Наше древо | … | … | … |
| member | papa | name | Артём | … | … | … |
| event | birth-masha | title | Родилась Маша | … | … | … |

- `kind` = `global` (шапка семьи), `member` (человек), `event` (событие);
- `id` — идентификатор объекта (`-` для глобальных полей);
- `field` — имя поля:
  - глобальные: `familyName`, `familySubtitle`;
  - человек: `role`, `name`, `nickname`, `birthday`, `about`, а также `habits[0]`, `quotes[0]`,
    `wishlist[0].title`, `wishlist[0].note`, `wishlist[0].url` (индекс — номер элемента);
  - событие: `date`, `title`, `text`, `place`;
- пустая ячейка = «не менять»; `-` в `wishlist[n].note` или `wishlist[n].url` = удалить поле;
- состав массивов (добавить/убрать пункт списка желаний, привычку, цитату) таблица не меняет —
  это делается правкой JSON (или напишите мне).
- `import_texts.js` не переформатирует JSON (правки точечные, отступы и CRLF
  сохраняются), проверяет формат дат и печатает отчёт.

Идемпотентность: повторный импорт без правок ничего не меняет.
После импорта обязателен полный перезапуск приложения и
«Перезагрузить данные» в настройках.

> Примечание: файлы `.ps1` сохранены в UTF-8 **с BOM** — Windows PowerShell 5.1
> иначе читает их как ANSI и ломается на кириллице. При правке скриптов в
> редакторе сохраняйте кодировку UTF-8 with BOM. Это относится только к `.ps1`;
> `.js`-скрипты — обычный UTF-8 без BOM.
